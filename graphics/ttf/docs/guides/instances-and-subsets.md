# Variable instances and subsetting

## Resolve a variable instance

Coordinates use four-byte big-endian OpenType tags. Unspecified axes use their
font defaults, supplied values are clamped to axis ranges, and `avar` mapping is
applied during normalization.

```csharp
const int WeightAxis = 0x77676874; // wght
const int OpticalSizeAxis = 0x6F70737A; // opsz

FontFace face = package.GetFace(0);
FontCoordinates coordinates = new FontCoordinates();
coordinates.Set(WeightAxis, 650);
coordinates.Set(OpticalSizeAxis, 12);

FontInstance instance = face.CreateInstance(coordinates);
NormalizedFontCoordinates resolved = instance.GetCoordinates();
byte[] staticFont = instance.CopyStaticSfntBytes();
```

`CreateDefaultInstance()` works for static and variable faces.
`CreateNamedInstance(index)` selects a face-defined named location. Inspect the
resolved coordinates rather than assuming a requested value survived clamping.
The static SFNT removes live variation dependencies and resolves conditional
layout feature variations deterministically.

Keep one `FontInstance` for every operation that must agree. Mixing outlines,
metrics, shaped runs, subsets, or PDF resources from different normalized
coordinates produces invalid positioning and mappings.

## Build a subset

Accumulate every use before building. Text adds cmap-mapped glyphs; explicit
glyphs cover non-text uses; shaped runs are preferred for real text because they
preserve substitutions and Unicode relationships.

```csharp
FontSubsetOptions options = new FontSubsetOptions();
options.SetLayoutPolicy(FontSubsetLayoutPolicy.Retain);
options.SetColorPolicy(FontSubsetColorPolicy.Retain);
options.SetVerticalPolicy(FontSubsetVerticalPolicy.Retain);

FontSubsetBuilder builder = new FontSubsetBuilder(instance, options);
builder.AddText("Hello");
builder.AddGlyph(37);
builder.AddPalette(0);

FontSubsetResult result = builder.BuildResult();
byte[] fontBytes = result.CopyFontBytes();
int[] oldToNew = result.GetOldToNewGlyphMap();
FontSubsetTableReport tables = result.GetTableReport();
```

Add only policies the output needs. Retaining layout, vertical, or color tables
adds their dependency closure and can substantially increase output size.
Compact mode renumbers glyphs; use the returned maps everywhere downstream.
Unknown tables cannot safely survive compact renumbering because their glyph
references are unknown.

The compatible profile retains conventional interoperability glyphs, drops
hint, layout, vertical, and color data by default, retains safe metadata, and
changes a requested subset to full-font output only when the rights flags
prohibit subsetting but otherwise permit embedding. Strict mode rejects that
policy conflict instead.

After building, inspect `GetDiagnostics()`, `GetRepairs()`, and
`GetEmbeddingDecision()`. The requested mode is not necessarily the effective
mode. Reopen generated bytes with `new FontLoader().LoadFromBytes` and options
from `new FontApiFactory().CreateStrictLoadOptions` as an integration check
before persisting or embedding them.
